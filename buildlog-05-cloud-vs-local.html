Cloud vs Local AI,
measured on my own fleet

Local AI isn't a worse cloud — it's a different tool. So I benchmarked my whole ladder — 1.5B, 3B, 7B on my own hardware — against a frontier model instead of guessing. Real timings, real answers, real failures. The house rule that came out of it: AI is an accelerator, not an authority.

Cloud = the ceiling

Frontier reasoning, few factual misses, effectively unlimited by your silicon — but your prompt leaves the network, it costs per token, and it's dead without internet.

Local = the floor

Private, $0 per request, works with the internet down, fast on small models — but capped by a CPU with no GPU, so it hallucinates on hard questions.

01The box under test

No cherry-picking. This is the actual hardware running the house voice assistant, on the private link, no cloud in the loop.

LOCALThinkPad X1 Carbon — Intel i5-6200U, 4 threads, no usable GPU, 7.6 GB RAM. Model qwen2.5:1.5b (1.0 GB) on Ollama, CPU inference. Whisper + Piper on a Pi over the private link.
CLOUDA hosted frontier model (Claude-class), measured live via the claude CLI on the same four prompts — see the caveat under the speed table about its ~7 s fixed startup cost.

Read it in one line: easy prompts — every size is right, so the tiny fast 1.5B wins. Hard prompts — quality climbs with size (the 1.5B called nmap -sV "OS detection," the 7B nailed it and flagged the legal risk) but speed collapses inversely, and the chip matters as much as the model: the 1.5B gave a wrong answer in 38 s while the 7B gave the right one in 72 s on the GPU-less ARM. That gap is the whole case for verify, don't trust.

05When to reach for which

Mapped to what actually runs on the fleet.

Local first

  • Always-on house & Mom voice
  • Quick commands, status checks
  • Offline / power-out resilience
  • Anything privacy-sensitive
  • Cheap, repetitive tasks

Cloud when it's hard

  • Real reasoning & planning
  • Code review you'll ship
  • Correctness-critical: CVEs, exploit logic
  • Config you're about to run for real

The GhostGrid pattern

  • Local-first for speed + privacy
  • Escalate to a bigger model on hard tasks
  • Verify whatever comes back
  • Floor + ceiling, not either/or

06The verdict: cloud-first for the work that matters

After all the homelab pride, the honest call — don't let it talk you out of the sharper tool.

Default to cloud when it counts

  • Learning, shipping code, pentest analysis
  • Anything a wrong answer costs you
  • Right on all four, fast, caught what local missed
  • A pro reaches for the sharpest tool — no guilt

Keep local for what it's FOR

  • Always-on house & Mom voice
  • Quick offline commands
  • Private stuff that shouldn't leave the LAN
  • Works when the grid's down

The local build is the gym

  • You run it because doing it yourself is the skill
  • Worth more to the career than its answers
  • Owning the stack > renting every brain cell
  • Either way — verify

Point your brain at cloud when it counts; let local run the house and the reps. Use cloud without guilt for the real work, keep local because you own it and it's teaching you — and either way, verify. The 1.5B told me -sV means "OS detection" with a straight face. That's why the tool never gets the final word.
